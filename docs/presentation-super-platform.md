## 2. 현재 코드 감사 (이번 작업 전)

| 구분 | 레퍼런스 대비 상태 | 판단 |
|---|---|---|
| 발표 화면 단축키 | PowerPoint 와 거의 동일(번호+Enter, B/W, Ctrl+P/L/A/H/S, 펜 · 레이저 · 확대 · 모든 슬라이드 · Alt+F5) | **이미 충분** — 다시 만들지 않음 |
| 발표자 보기 | 현재 · 다음 장, 노트, 경과 시간, 시계, 초기화, 노트 글자 크게 | **빠짐**: 목표 · 남은 시간 경고, 타이머 멈춤, 장별 시간, 번호 이동, 검은/흰 화면, 좁은 화면 배치(400px 고정 열 → 휴대폰에서 가로 넘침) |
| 리허설 | 없음 (타이머만) | **빠짐**: 장별 시간 기록 · 저장 · 비교 |
| 슬라이드 품질 점검 | 용량 점검만 있음 | **빠짐**: 글 양 · 글자 크기 · 대비 · 밖으로 나간 상자 |
| 교안의 계획 시간 | 사용자 교안 노트에 이미 `[1분]` · `(2분)` · `⏱ 1분` · `[0:30]` 형식으로 적혀 있음 | 도구가 **읽지 않고 있었음** → 그대로 활용 |
| 청중 참여(QR · 퀴즈) | 없음 (링크 요소만) | 서버 없이 가능한 QR 부터 다음 세션 |
| 교안 구조 템플릿 | 레이아웃(제목 · 목차 등)은 있으나 도입 · 전개 · 정리 묶음 없음 | 다음 세션 |
| 휴대폰 | 발표 화면은 스와이프 · 메뉴 대응됨. 발표자 보기는 넘침 | 이번에 고침 |
| 동기화 | 발표자 보기는 BroadcastChannel(같은 브라우저 · 같은 기기)만 | 휴대폰을 리모컨으로 쓰려면 중계 서버 필요 — 비용 큼, 보류 |

## 4. 이번에 만든 것

- **`app/prestime.js`(새 파일)** — 목표 시간 · 지난 발표 기록(최근 5회) · 노트 계획 읽기. `localStorage` 의 `pres:target:<교안>` · `pres:runs:<교안>` 에만 저장하고, **교안 파일(decks/*.json)은 바꾸지 않습니다.** 기존 저장 형식은 그대로입니다.
- **발표자 보기**: 목표 __분 입력 → 남은 시간(10% · 최소 2분 남으면 노랑, 넘기면 빨강 깜빡임). 멈춤/계속/시작. "이 장 00:41 · 지난 기록 00:35 · 계획 01:00 · 지난 기록보다 01:10 늦음". 번호+Enter, B/W(발표 화면에 반영 + 「검은 화면 중」 표시). 820px 이하에서 한 줄로 쌓임.
- **발표 화면**: 장별 시간을 잼(멈춘 시간 · 끝 화면에 머문 시간 제외). 끝 화면에 발표 시간 · 목표와 차이 · 오래 머문 장 3개. 1분 미만은 기록하지 않음. 창을 닫아도(pagehide) 저장. `T` 타이머에 남은 시간 · 멈춤 표시.
- **편집기 아래쪽 `점검`** (고칠 곳 수가 단추에 표시) — 「슬라이드 품질」: 글자 24px 미만, 대비(4.5:1 · 큰 글 3:1, 같은 색 짝은 한 줄로 묶어 "디자인 색 하나로 한 번에 고쳐짐" 안내), 한 장 150자 초과, 슬라이드 밖 글 상자, 빈 글 상자. 줄을 누르면 그 장 · 그 개체로 감. 「발표 시간」: 목표 · 노트 계획 합계 · 지난 발표의 장별 막대(계획보다 25% 넘게 길면 주황).
- **노트 계획 읽기 규칙**: 첫 줄 맨 앞 괄호/⏱ 안의 `N분`, `N초`, `N분 M초` = 이 장의 길이. `[m:ss]` 로 시작 = 이 장의 시작 예정 시각. `[PART 1 · 약 15분]` 처럼 PART · 부 · 전체 · 총 이 들어간 것은 묶음 시간이라 무시.
- 단독 HTML 내보내기 · 서비스 워커 캐시에 `prestime.js` 추가.

### 알려진 한계 (솔직하게)

- 기록은 **그 브라우저에만** 남습니다. 집 PC 에서 리허설하고 강의장 PC 에서 보면 기록이 없습니다(GitHub 동기화는 교안 파일 형식을 바꿔야 해서 이번엔 하지 않음).
- 타이머는 지금처럼 **첫 번째로 넘길 때** 시작합니다. 첫 장에서 오래 말하면 그 시간은 기록되지 않습니다 → 발표자 보기의 **시작** 단추를 먼저 누르세요.
- 대비는 단색 · 그라데이션 바탕만 잽니다. 사진 위 글, 반투명 · 아주 큰 장식 글자, 문장부호만 있는 글은 뺍니다. 글자 굵기는 상자 기본값만 봅니다.
- 글 양 150자는 경험치입니다(Mayer 간결성의 정량 기준은 없음). 카드 여러 개로 된 장은 많게 나올 수 있습니다.

## 5. 다음 세션 할 일

1. **QR 요소**: 주소를 넣으면 QR 그림(오프라인에서도 만들 수 있게 작은 생성 코드 포함). 뒷자리 스캔용 최소 크기 안내(슬라이드 높이의 30% 이상).
2. **교안 구조 템플릿**: 「도입(주의 · 목표 · 왜 지금) — 전개(사례 · 방법 · 실습) — 정리(요약 · 확인 퀴즈 · 행동 요청)」 슬라이드 묶음 한 번에 넣기. 가네 · Knowles 근거.
3. **퀴즈 슬라이드**: 보기 → 클릭으로 정답 공개(기존 단계 애니메이션 활용) 묶음.
4. 점검기 확장: 제목이 단어만 있는 장(주장-근거 방식 안내), 동영상 · 그림 대체 텍스트.
5. 발표 기록을 교안 옆 파일(`decks/<이름>.times.json` 등)로 동기화할지 결정 — 다른 세션의 GitHub 동기화 형식과 맞춰야 함.
