# DPV 에이전트 구성

`.claude/agents/` 의 에이전트 8개입니다. Claude Code 가 이 저장소에서 열리면 자동으로 쓸 수 있습니다. 이름을 불러 맡길 수도 있습니다(예: "challenger 에이전트로 견제해 줘").

| 순서 | 에이전트 | 맡는 일 | 고치나 |
|---|---|---|---|
| 1 | technique-scout (기법 수집) | 움직임 · 상호작용 기법과 언제 쓰고 쓰지 말지 | 아니오 |
| 1 | design-reference-scout (디자인 · UI 레퍼런스) | 실제 제품 · 디자인 시스템 화면과 DPV 화면 비교 | 아니오 |
| 2 | challenger (견제) | 만들기 전: 정말 필요한가, 더 단순한 방법은 | 아니오 |
| 3 | applier (활용) | 승인된 항목 구현 · 직접 시험 · 커밋 | 예 |
| 4 | reviewer (검토) | 코드가 깨지는 곳 찾기 | 아니오 |
| 4 | challenger (견제) | 만든 뒤: 매일 쓰는 흐름을 해치지 않는가 | 아니오 |
| 5 | judge (판사) | 검토 · 견제 · 활용 주장을 증거로 판결 | 아니오 |
| 6 | auditor (감사관) | 보고 · 출처 · 규칙 · 보안이 사실인지 감사 | 아니오 |
| 7 | final-decider (최종 결정) | 병합 · 고친 뒤 병합 · 보류 · 폐기 결정, 보고 초안 | 아니오 |

같은 순서 번호는 동시에 돌릴 수 있습니다. 병합은 최종 결정 뒤에 applier(또는 메인 세션)가 CLAUDE.md 순서대로 합니다.

## 비용을 생각해서 규모별로 나눠 씁니다

에이전트 하나가 대략 한 번의 조사 · 검토만큼 사용량을 씁니다. 8개를 모두 돌리면 같은 일을 혼자 할 때의 몇 배가 됩니다. 그래서 다음처럼 나눕니다.

- **작은 수정**(문구 · 버그 하나): applier → reviewer. 나머지는 생략합니다.
- **보통 기능**(화면 하나 · 기능 하나): scout 하나 → applier → reviewer + challenger → judge.
- **큰 개편**(여러 작업장 · 공용 부품 · 데이터 형식 변경): 8개 전부 돌립니다.

사용자가 "전체 파이프라인"이라고 하면 규모와 상관없이 8개를 모두 씁니다.
